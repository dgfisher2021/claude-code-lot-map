# Wave 1 Implementation Plan

**Status:** done. Shipped in 0.10.0 (PR #5, merged 2026-11-16). What it left is in the spec under "Left after wave 1", and moved to wave 2.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build wave 1 of the improvements spec (items 1–10). The map and the rows under it should say at a glance whether a session works, waits on you or failed, and how far through its plan it is.

**Architecture:**

- **State on the board.** New facts live on the `Board` atom (`types/index.d.ts`), set by hooks in `hooks/register.tsx`.
- **Pure functions read them.** These live in `hooks/map.ts`: `stateOf`, `feedLines`, `pinnedLines`, `planLines` and `describeNow`.
- **Every surface uses them:**
  - the SVG drawing (`drawMap`)
  - the cell map (`hooks/raster.ts`)
  - the pane (`ui.render` in `register.tsx`)
  - the window, through `feed.json` and `renderer/view.mjs`
- **Words in `hooks/text.ts`** for all seven languages.

**Tech Stack:** a TypeScript Claude Code mod (hooks API), with Node `renderer/view.mjs` for the Sixel window.

**Spec:** `claude/lot-map-improvements-spec.md`, items 1–10.

## Global Constraints

- **Labels hold names, never content.** A task's subject and a subagent's description are the model's own short words. They're shown as shell descriptions are, cleaned (`clean`) and cut.
- **Every word a person reads** goes in `hooks/text.ts`, in all of `en`, `ru`, `es`, `fr`, `de`, `it` and `pt`.
- **Loader rules:**
  - `$.env.get` takes a literal name.
  - A function that receives `$` must be declared at the top of its file.
  - Hooks are written `on('<event>', hook)`.
- **Every hook passes its event on unchanged** and returns what came back. Map work goes inside `quietly(...)`.
- **Tests run in `claude plugin test .`:**
  - Stubs must be registered before the first `$` call.
  - `mock.env` copies its object.
  - A tool's text is the `text` field of the `tool.call` answer.
- **Checks:**
  - `claude plugin validate .`: its one existing warning, the `widget` placement, stays.
  - `tsc` strict via `$CLAUDE_JOB_DIR/tmp/tsc/tsconfig.json`, including `hooks/` and `types/` of this worktree and the bundled `claude-code.d.ts`.
  - Prettier 3.3.3: `--no-semi --single-quote --arrow-parens avoid --print-width 160`, on edited code only; don't reformat untouched lines.
- **Commits** carry no Claude attribution and no symbols such as the row marks (the commit guard refuses them).
- **Version** `0.10.0`. One CHANGELOG section, written as each task lands.

## Review Focus

1. **Long or wide words in a subject or label.** A subject with emoji or CJK, 200 characters long, is cut to 60 characters, keeps no control characters, and never widens a row past the pane. Pinned in Task 9.
2. **Task tools that misbehave.** A TaskUpdate for an id never created, a TaskCreate that failed, or an empty TodoWrite leaves no ghost rows and throws nothing. Pinned in Task 9.
3. **A subagent with no `agent.spawn` label** (a workflow agent): its rows show no prefix, and its failure still marks a dot. Pinned in Task 6.
4. **The state word in every language** fits under the core in a 44-column dock, one narrow glyph per cell. Pinned in Task 2.
5. **A window 20 rows tall with a plan, pinned work and rows:** the map keeps its minimum, the list cuts, and nothing scrolls. Pinned in Task 10.
