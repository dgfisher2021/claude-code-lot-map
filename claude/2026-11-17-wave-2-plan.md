> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build wave 2 of the improvements spec (items 11–20) as version 0.11.0. The map should stay quiet under an organisation's guard, take upstream's fixes, say when a permission prompt waits on you, and answer what changed and what it costs.

**Architecture:** as in wave 1:

- **State on the board.** New facts live on the `Board` atom (`types/index.d.ts`), set by hooks in `hooks/register.tsx`.
- **Pure functions read them,** in `hooks/map.ts`. Classification moves to `hooks/classify.ts`, a near copy of upstream's, so later upstream fixes come in as a file copy.
- **Every surface uses them:** the SVG (`drawMap`), the cells (`hooks/raster.ts`), the pane (`ui.render` in `register.tsx`), and the window through `feed.json` and `renderer/view.mjs`.
- **Words in `hooks/text.ts`,** in all seven languages.

**Tech Stack:** a TypeScript Claude Code mod (hooks API), with Node `renderer/view.mjs` for the Sixel window.

**Spec:** `claude/lot-map-improvements-spec.md`, items 11–20, and its sections "Left after wave 1" and "Upstream since the fork".

## Global Constraints

- **Labels hold names, never content.** A file in "changed" goes by the label `classify` gives it (its last two path parts), never by its text.
- **Every word a person reads** goes in `hooks/text.ts`, in all of `en`, `ru`, `es`, `fr`, `de`, `it` and `pt`. Each new mark on the map or in the rows gets a line in `legend`, and the legend test's line count follows.
- **Loader rules:**
  - `$.env.get` takes a literal name.
  - A function that receives `$` must be declared at the top of its file.
  - Hooks are written `on('<event>', hook)`.
- **Every hook passes its event on unchanged** and returns what came back. Map work goes inside `quietly(...)`.
- **Tests run in `claude plugin test .`** (about 20 s):
  - Stubs must be registered before the first `$` call.
  - `mock.env` copies its object.
  - A tool's text is the `text` field of the `tool.call` answer.
  - A test file may import only the mod's own files and `claude-code`; `../renderer/*.mjs` works, `node:*` doesn't.
- **Checks:**
  - `claude plugin validate .`: its one existing warning, the `widget` placement, stays.
  - `tsc`: `npx -y -p typescript@5.6.3 tsc -p $CLAUDE_JOB_DIR/tmp/tsc/tsconfig.json`, run from that folder. It covers `hooks/` and `types/` with the current `claude-code.d.ts`. No errors after Task 1.
  - Prettier 3.3.3: `npx -y prettier@3.3.3 --no-semi --single-quote --arrow-parens avoid --print-width 160 --write <files>` on edited code only. Markdown with plain `prettier@3.3.3 --write`.
- **The board's shape tag** in `register.tsx` (`{ shape: 'board-3' }`) becomes `'board-4'` in the first task that adds a field to `Board` or `Entry`, once for the release.
- **Commits** carry no Claude attribution and no symbols such as the row marks; the commit guard refuses them.
- **Version** `0.11.0` in `.claude-plugin/plugin.json`. One CHANGELOG section, `## 0.11.0 (2026-11-17)`, written as each task lands. README and PRIVACY follow each change.
- **The worktree guard** refuses complex inline shell. Write scripts to `$CLAUDE_JOB_DIR/tmp` and run them.

## Review Focus

1. **A `/clear` is not a compaction.** The context falls to nothing at a `/clear`; with `guardedHooks` off, no "compacted" row may follow. Pinned in Task 1.
2. **A mode that settles an ask at once never flashes "needs you".** In `acceptEdits`, `bypassPermissions` or `dontAsk` the call runs (or is refused) within milliseconds of the `ask`; the wait shows only after one second unsettled. Pinned in Task 5.
3. **A turn a background task's notification starts is no turn of the person's.** It opens no new turn header, and its calls count on the turn they fall in. Pinned in Task 6.
4. **Work meant to run long never warns.** A background task (a dev server, a monitor) and a wait on the person never read as "running long" or "nothing happening". Pinned in Task 8.
5. **A long name never widens a line.** A changed file named with emoji or CJK, 200 characters long, and a legend line in German, stay within the pane's width as the existing rows do. Pinned in Tasks 4 and 7.
